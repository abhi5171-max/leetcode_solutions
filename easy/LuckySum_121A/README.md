# Lucky Sum — Codeforces

## Problem Description

Petya loves **lucky numbers**. A lucky number is a positive integer whose decimal representation contains only the digits **4** and **7**.

For example:

* `4`, `7`, `44`, `47`, `74`, `777` → Lucky
* `5`, `17`, `46`, `123` → Not lucky

For any integer `x`, define `next(x)` as the **smallest lucky number greater than or equal to `x`**.

Given an interval `[l, r]`, calculate:

$$
next(l) + next(l+1) + \cdots + next(r)
$$

---

## Approach

The important observation is that `next(x)` remains the same for a range of consecutive numbers.

For example, consider:

```text
l = 2, r = 7
```

The relevant lucky numbers are:

```text
4, 7
```

Therefore:

```text
2 → 4
3 → 4
4 → 4

5 → 7
6 → 7
7 → 7
```

So the answer is:

$$
3 \times 4 + 3 \times 7 = 33
$$

Instead of checking every number individually, we:

1. Generate all lucky numbers.
2. Sort them.
3. Process the interval `[l, r]` in segments.
4. For each lucky number `x`, all currently unprocessed values up to `x` have `next(value) = x`.
5. Add the contribution of the entire segment at once.

---

## Generating Lucky Numbers

Every lucky number can be generated by appending either `4` or `7`.

For example:

```text
4
7

44
47
74
77

444
447
474
477
...
```

A recursive function generates these numbers.

Since `r ≤ 10^9`, only a very small number of lucky numbers are required.

---

## Python 3 Solution

```python
l, r = map(int, input().split())

lucky = []


def generate(x):
    if x > 10**10:
        return

    if x:
        lucky.append(x)

    generate(x * 10 + 4)
    generate(x * 10 + 7)


generate(0)
lucky.sort()

ans = 0
current = l

for x in lucky:
    if x < l:
        continue

    if current > r:
        break

    end = min(r, x)

    # Every number from current to end has next(number) = x
    ans += (end - current + 1) * x

    current = end + 1

    if current > r:
        break

print(ans)
```

---

## Example

### Input

```text
2 7
```

### Processing

```text
Lucky numbers: 4, 7

2, 3, 4 → next = 4
5, 6, 7 → next = 7
```

Therefore:

```text
4 + 4 + 4 + 7 + 7 + 7 = 33
```

### Output

```text
33
```

---

## Complexity

There are only:

$$
2^1 + 2^2 + \cdots + 2^{10} = 2046
$$

lucky numbers with at most 10 digits.

Therefore:

* **Time Complexity:** `O(K log K)`, where `K` is the number of generated lucky numbers
* **Space Complexity:** `O(K)`

With `K ≤ 2046`, this is easily within the limits.

---

## Key Takeaway

The main trick is to **group consecutive values having the same `next(x)`** rather than calculating `next(x)` separately for every number in `[l, r]`.

This reduces the problem to generating lucky numbers and processing only a few thousand segments.
